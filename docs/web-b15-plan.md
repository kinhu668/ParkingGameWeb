# ParkingGameWeb 批次 B1.5：三項玩家回饋

2026-11-19 · 基準 `main@cdf4fed`（B1 已上線）· 規格 `/workspace/ParkingGame-web-spec-v0.2.md`（唯讀）。
每一步的觀察、截圖路徑與 e2e 紀錄在 `~/parking-dev/logs/web-b15-progress.md`。

使用者的原話：

> 後車的時候，越接近撞到後面的東西，就beep beep聲音的頻率就加快。然後下雨的場景和打雷應該加上效果音。撞到隔壁車的時候，那個車應該比較dramatic地動一下，好像真的被撞了一樣。

## 範圍

1. **倒車雷達**：B1 固定 0.8 秒一聲的倒車嗶聲，改成越靠近車尾後面的東西嗶得越快，貼到快碰到時變成一個長音。
2. **天氣的聲音**：下雨（`rain`、`storm`）有雨聲，雷雨的每一道閃電之後有雷聲，雨後（`wet`）只有零星的滴水聲。全部用 Web Audio 合成，沒有音檔。
3. **被撞的車會晃**：撞到停著的車（各款停放車、衝浪休旅車、包裹貨車、救護車、餐車），那台車像真的被撞到一樣在懸吊上晃幾下再停住。只是畫面，碰撞盒、停車判定與官方路線都不變。

4. **背景音樂**（範圍追加）：兩首事先做好的循環（白天、夜晚），解鎖後才下載；暫停面板可以關掉。

不改：`session.ts` 的形狀、`collision.ts`、`bicycleModel.ts`、`levelSchema.ts`、`core/controls.ts`、任何官方路線／時間／碰撞次數。不新增 npm 套件、圖片、字型；音檔只有使用者核准的那兩個 MP3。

## 設計紀錄

（這個環境聽不到聲音：聲音靠假的 AudioContext 驗接線與排程，音量與頻譜用無頭 Chrome 的 OfflineAudioContext 量，
e2e 讀遊戲自己的唯讀旗標與實際發出的網路請求。好不好聽要請人在真的裝置上聽。）

### 1. 倒車雷達

- **量什麼**（`src/level/rearSensor.ts`，純函式）：車尾保險桿往正後方到最近的碰撞盒的淨距離。看的是 `collision.ts`
  用的同一批盒子（關卡的障礙物加四面邊界牆），所以「雷達說還有多遠」與「再退多遠會被記一次碰撞」是同一把尺。
  做法是一條與車同寬、每邊多 0.25 ft 的帶子往後掃，算每個盒子落在帶子裡的那一塊最近的一點（不是幾條射線：斜放的車的角不會從兩條射線中間漏掉）。
  每邊只多 0.25 ft：倒進兩台車中間時，兩旁的車不會讓雷達一直叫。只看正後方，不知道方向盤打了多少。
- **節奏**（`src/audio/soundDirector.ts` 的 `beepIntervalS`、`beepLengthS`；常數在 `VOICE_SETTINGS.beep`）：
  8 ft 以外維持 B1 的 0.8 秒一聲（選「照舊慢慢嗶」而不是「遠的時候不出聲」：一掛 R 檔就有聲音，才知道雷達開著；變快是聽「變化」）。
  8 ft → 1 ft 線性縮短到 0.13 秒一聲；不到 1 ft 變成一個長音，要退到 1.25 ft 以外才變回一聲一聲（不在邊界上來回跳）。
  8 ft 是因為倒車常見的 3–5 mph 從 8 ft 到 1 ft 要 1–1.6 秒，聽得出越來越急；再短只剩一兩聲。
  一聲的長度最多佔間隔的 55%（平常 0.22 秒），上一聲結束後至少隔 0.03 秒才有下一聲，所以不會疊在一起。
- **時間**：相位仍然走模擬時間（暫停時停住）；context 停住太久時新的嗶聲照 B1 的規則丟掉，長音是「狀態」，恢復出聲後補上。
- `__parkingGame.audio()` 多了 `rearDistanceFt`、`beepIntervalS`（長音是 0）、`continuousBeep`。

### 2. 天氣的聲音

- 全部合成（`src/audio/ambience.ts`，常數在 `AMBIENCE_SETTINGS`），雜訊與雨滴都來自固定種子（`core/rng.ts`）。
- **雨（`rain`）**：不是一條白雜訊。底層是 4 秒循環的粉紅雜訊（左右聲道各一段、首尾交叉淡化）→ 高通 500 Hz → 低通 7 kHz；
  上面疊一層雨滴的「啪搭」（5.3 秒的循環裡每秒 70 顆衰減很快的短雜訊，多數很小聲、少數幾顆很近）→ 帶通 3.8 kHz；
  底層的音量再加一個 0.11 Hz、±12% 的緩慢起伏。
- **雷雨（`storm`）**：同樣的做法但更大（底層 0.26 對 0.16、每秒 130 顆雨滴、起伏 ±22%），多一層 380 Hz 以下的低頻轟轟聲。
- **雨後（`wet`）**：只有零星的滴水（兩段 7 秒與 11 秒的循環，合起來 77 秒才重複；每一滴是音高往上滑的短正弦）。
  沒有雨的底層：雨已經停了，有底噪聽起來會像還在下。
- **雷聲**：場景每多打一道閃電（`GameScene.lightningStrikes()`，與畫面上的閃光是同一份 `effects/lightning.ts` 的時間表、
  同一個時鐘），聲音導演就送一個 `thunder` 指令，引擎排在 0.3–2 秒之後（`thunderPlan(第幾道)`：越近越快到、越響）。
  轟隆聲是雜訊過低通（截止頻率從 260–1100 Hz 一路滑到 90 Hz）加 43、58 Hz 兩個正弦，音量 0.1–0.6 秒起來、整聲 3–6 秒、
  中間有兩個慢的起伏；比較近的那一半開頭多一聲脆的（高通 900 Hz、0.32 秒）。一幀裡跳過好幾道（分頁從背景回來）只排最後一道。
- **接線**：聲音 → 環境聲匯流排 → 主音量 → 限幅器；沒有環境聲的天氣不建立這個匯流排。解鎖後 1 秒淡入；暫停、背景分頁、
  等玩家按新鍵時整個 context 停住，它也跟著停。重來時先壓下去（0.12 秒）、0.3 秒後再回來；停妥或失敗的結算畫面雨照下。
- **`?fx=off`**：雨聲與滴水聲照天氣走（聲音不是視覺特效）；雷聲跟著畫出來的閃電，`?fx=off` 沒有閃電也就沒有雷聲。
  「減少動態效果」不影響聲音。
- `__parkingGame.audio()` 多了 `ambience`（`'rain' | 'storm' | 'drips' | null`）與 `thunders`（累計排了幾聲）。

### 3. 被撞的車會晃

- **模型**（`src/level/hitSway.ts`，純函式；常數在 `SWAY_RULES`）：每台被撞的車一個二維的阻尼彈簧（車身本地的橫向與縱向），
  1.8 Hz、阻尼比 0.28（稍微欠阻尼，晃過頭一兩次，約 1.2 秒停住），用解析解走每一幀（不論一幀多長結果都一樣；`dt = 0` 一個位元都不變）。
  推的方向是玩家車與那台車兩個矩形「卡得最淺」的那條邊法線；幅度依撞擊車速從 15%（輕輕一碰）線性到 6 mph 以上的滿格。
  滿格 = 側傾 4°、俯仰 2°、整台被推開 3 英寸；全部會彈回原位，沒有留下任何位移。還在晃時再被撞，新的一推加在現在的速度上（有上限）。
- **畫面**（`src/effects/swayMeshes.ts`）：整台車（烤漆、其餘部分、車牌上的字、車身上的字樣、亮著的警報燈與光暈）繞
  「車底正中央的地面」傾斜再平移。輪子與車身併在同一個網格裡，所以是整台一起傾（4° 時一側的輪子離地約 2 英寸）。
  停了就把原本的矩陣放回去。碰撞盒、停車判定、鏡頭的擋塊都不動。實例的矩陣經過遮擋半透明（`occlusionFade.place`）改：
  正被淡成半透明的車動的是它的替身。
- **減少動態效果**：反應留著，但縮成 30%（輕輕一點）。`?fx=off`：不晃（同一個網址的畫面每次相同）；`?cam=` 定格本來就沒有碰撞。
- `__parkingGame.sways()`：正在晃的車的障礙物索引與現在的幅度（1 = 滿格）。

### 4. 背景音樂（範圍追加，2026-11-19 使用者核准）

- **兩個音檔**：`public/audio/bgm_day.mp3`（773,612 B）與 `public/audio/bgm_night.mp3`（739,916 B），共 1,513,528 B（約 1,513 KB），
  照交付的檔案原樣複製（MP3 96 kbps、48 kHz 立體聲，沒有重新編碼）。Vite 把 `public/` 原樣放進 `dist/audio/`；
  程式用相對網址 `audio/bgm_*.mp3`，放在 GitHub Pages 的子路徑底下也找得到。
- **什麼時候下載**（`src/audio/musicPlayer.ts`）：第一個手勢解鎖之後，而且音樂開著、沒有靜音，才 `fetch` + `decodeAudioData`；
  第一次載入與第一幀都不碰它。只下載這個畫面要播的那一首，一頁只下載一次（解碼好的緩衝區就掛在循環的音源上）。
  下載不到或解不出來就是沒有音樂：不丟例外、不寫 console、不重試。
- **哪一首**（`src/audio/music.ts` 的 `musicTrackFor`）：夜晚與雷雨是 `bgm_night`，其餘（晴、黃昏、雨、雨後）與關卡選擇畫面是 `bgm_day`；
  看的是實際用的天氣（`?weather=` 蓋過關卡的）。
- **循環**：`AudioBufferSourceNode`、`loop = true`。循環長度以原始取樣數為準（白天 3,091,200、夜晚 2,956,800 個取樣 = 64.4／61.6 秒）。
  檔頭（Info 標籤）寫了編碼器墊的取樣（開頭 576；結尾 1344／960），格數 × 1152 減掉它們剛好是原始長度；
  解碼出來剛好是原始長度就從頭循環到尾，比較長（解碼器沒有裁）就從開頭第 1105 個取樣開始循環同樣的長度（`musicLoopS`）。
- **混音**：音源 → 開關與淡入 → 音樂匯流排（0.35）→ 主音量 → 限幅器，與 sfx、環境聲並排。開始播時 1.5 秒淡入。
  有車輛警報或救護車警笛在響時壓到一半（約 −6 dB，時間常數 0.15 秒），全部停了再慢慢回來（0.6 秒）；倒車雷達、悶響、雷聲不壓。
  主音量與靜音照常作用；暫停、背景分頁、等玩家按新鍵時整個 context 停住，音樂也停在原地。重來不會讓音樂從頭開始。
- **開關**：暫停面板音量那一列下面多一顆「關閉音樂／開啟音樂」（寫的是按下去會發生的事，zh-TW 與 en 都有）。
  存在 `settings.audio.music`（預設開；沒有這一項或不是布林都當作開，不會讓存檔作廢；`SAVE_VERSION` 仍是 1）。
  靜音蓋過它：靜音時沒有音樂，也不下載。關掉時音源照走只是沒聲音，再打開就淡入接上。
- **關卡選擇畫面**：B1 這個畫面沒有聲音引擎，現在有一個只播音樂的（同一個引擎，沒有環境聲）。一樣要第一個手勢才開始；
  進關是換頁，所以音樂在新的一頁的第一個手勢之後重新開始（從頭、淡入）。`?show`、`?cam`、`?bench` 仍然沒有聲音引擎。
- `__parkingGame.audio()` 多了 `music: { track, state: 'idle' | 'loading' | 'playing' | 'off', ducked }`
  （`idle` = 還沒解鎖或載入失敗；`off` = 玩家關掉或靜音）與 `lightningStrikes`（場景打過幾道閃電，e2e 對雷聲用）。

## 怎麼試

線上：<https://kinhu668.github.io/ParkingGameWeb/>（聲音要先按一個鍵或點一下才會開始；手機是手指放開的那一刻）。

- **倒車雷達**：任何一關按 `R` 掛倒檔，按住 `W` 往後退。離後面的東西 8 ft 以外是慢慢的嗶聲，越近越急，不到 1 ft 變成長音；
  往前開一點或換回 D 檔就停。`?level=w1_l03`：起點直直往後退就是走道對面的車。
- **雨聲與雷聲**：`?level=w1_l08`、`?level=w1_l10`（雨）、`?level=w1_l07`（雷雨：看到閃光之後 0.3–2 秒聽到雷）、
  `?level=w1_l04`（雨後的滴水）。任何一關加 `&weather=rain|storm|wet` 也可以。
- **被撞的車**：`?level=w1_l07&weather=clear`，起點兩側都停著車：按住 `W` 加 `D`（方向盤往右打到底），約 1 秒後撞上右邊那台，
  它會側傾晃幾下。直直撞車頭或車尾（例如 `?level=w1_l09` 往前開撞救護車）是前後點頭。
- **背景音樂**：進任何一關按一個鍵之後淡入；夜晚關（`w1_l09`）與雷雨關（`w1_l07`）是另一首。`Esc` 暫停面板可以關掉。
  撞到車、警報響的那幾秒音樂會壓低。

## 已知限制

- **沒有人聽過**：這個環境沒有喇叭。接線、排程、時機用假的 AudioContext 與 e2e 的唯讀旗標驗證；音量與頻譜用無頭 Chrome 的
  OfflineAudioContext 量。雨聲像不像雨、雷聲夠不夠沉、音樂與音效的比例，要請人在手機與電腦上各聽一次。
- **倒車雷達只看正後方**：一條與車同寬的帶子往後掃，不看方向盤打了多少；倒車轉彎時側後方的東西要等進到車尾正後方才會讓它變急。
  也不分左右聲道。
- **被撞的車整台一起傾**：輪子與車身併在同一個網格裡，側傾時一側的輪子會離地一點、另一側陷進地面一點（幾英寸，晃動中不容易看出來）。
  晃動只是畫面：碰撞盒留在原位，所以晃到最遠的那一瞬間，看起來離玩家車遠了幾英寸，實際的碰撞邊界沒有動。
- **第一次撞到會卡一下**（B1 就有）：警報燈的著色器在第一次撞到時才編譯。晃動走的是模擬時間，卡完之後從頭晃起，不會被跳過；
  但卡很久的機器上（每幀最多補 0.25 秒）第一下的高點可能看不到。
- **音樂**：解碼後兩首各佔約 25 MB 記憶體（64 秒 × 48 kHz × 立體聲 × 32 位元浮點）；只會解碼這一頁要播的那一首。
  進關是換頁，所以從關卡選擇進關時音樂會斷掉、在新的一頁第一個手勢之後從頭淡入。關卡選擇畫面上第一個手勢通常就是點關卡卡片，
  所以那裡的音樂多半來不及聽到。解碼器如果只裁掉檔頭寫的 576 個取樣、沒有連自己的 529 個取樣延遲一起裁，循環接點會有約 11 毫秒的瑕疵
  （從長度看不出來，沒有另外偵測）。
- **雷聲與閃光的同步**：雷聲排在聲音的時鐘上、閃光走遊戲的時鐘；畫面卡住或幀率很低時兩者會差一點（幾十毫秒到一兩百毫秒），
  方向是雷聲不會早於閃光。
