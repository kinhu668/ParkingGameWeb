# 跟車鏡頭的避讓與開場鏡頭體檢

## 避讓（`src/render/gameCamera.ts`、`src/render/cameraBlockers.ts`）

近／遠距離跟車鏡頭原本只是放在車尾後方固定的距離與高度。車尾後面就是牆（巷子那一關的起點）時，鏡頭會落在牆裡面，
或落在比鏡頭矮的屋頂上方——從那裡往下看只看得到屋頂的磚，看不到車。現在每一幀都會檢查：

- **擋塊**：場景裡實心的東西各用一塊方塊代表，來源是擺設自己的登記（`props/occluders.ts`）——樓、牆、停著的車、子母車、
  巷子兩旁的整棟建築（`registerCameraBlockers`）。每一關、每一種環境都適用，沒有為哪一關另外寫座標。
  細桿、薄片（佔地小於 10 ft²）與標成 `passable` 的（路燈、樹）不算：掃過一根燈桿就把鏡頭拉近再放開，畫面會抽動，
  它們照舊交給遮擋半透明（`render/occlusionFade.ts`）。
- **擺位**（`resolveChasePlacement`）：從看向點（車身中心上方）往理想位置掃一顆半徑 1.6 ft 的球。
  1. 擋住的是矮的東西（頂面 ≤ 9 ft：車、子母車、矮牆），而且桿子抬高 15° 以內就能整根越過去 → 留在原本的距離，只是高一點。
  2. 否則（樓、高牆）沿原本的方向拉近到擋塊前面。
  3. 拉近後離看向點不到「最近距離」（近距離 12.5 ft、遠距離 13 ft；直式的手機畫面要「車寬 ≤ 畫面寬的一半」，會更遠）→
     把桿子往上抬，找最低的、夠遠的仰角（最多 68°）：鏡頭在車的後上方往下看。
  4. 越近視角越寬（最寬 72°），近看時整台車與前面的路才裝得進畫面。
  鏡頭永遠看向同一個看向點，所以位置變了俯仰自動跟著變，車留在畫面中央。
- **就位與平滑**：開場、重來、換鏡頭、畫面長寬比改變時直接就位。避讓的位移做平滑（擋塊讓開後慢慢回去）；
  平滑到一半的位置若被擋住，改用「直接到目標」與「沿視線拉回擋塊前面」兩者中離得近的那一個，所以鏡頭任何一幀都不在擋塊裡。
- 引擎蓋、駕駛座、俯視不變：視點在車身的佔地裡面，車進不去的地方它們也進不去。

數值都在 `renderConfig.ts` 的 `GAME_CAMERA_CONFIG.avoidance`。

## 開場鏡頭體檢

- **自動**：`tests/openingCamera.test.ts`（`npm test` 會跑）。每一關 × 五個鏡頭 × 四個畫質 × 橫式／直式，車在起點時：
  車的包圍盒投影在畫面裡、大小合理；用真的場景網格打 Raycaster，鏡頭與車身上 9 個點之間沒有被樓、牆、車擋住，
  鏡頭也不在實心的東西裡面；看得到車頭前面的場地。另外沿每一關的參考路線開一趟，逐幀檢查跟車鏡頭。
- **看圖**：`scripts/camera-audit/shoot.mjs` 把每一關 × 每個鏡頭的開場各拍一張，`sheet.py` 拼成聯絡圖。

  ```sh
  npm run build && npx vite preview --port 4173 --strictPort &
  node scripts/camera-audit/shoot.mjs
  python3 scripts/camera-audit/sheet.py e2e/output/camera-audit e2e/output/camera-audit-sheet.png
  ```
- e2e：`e2e/camera.spec.ts` 用巷子關（w1_l10）的開場確認遠、近距離跟車都在巷子裡、畫面中央是車。
  `window.__parkingGame.camera()` 回報鏡頭的位置、視角與車在畫面上的位置（唯讀）。
